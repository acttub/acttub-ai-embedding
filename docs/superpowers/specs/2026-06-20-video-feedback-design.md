# 비디오 피드백 파이프라인 설계 (MVP)

작성일: 2026-06-20

## 목표

사용자 영상을 입력받아, 기준(올바른) 영상과 비교하여 **"어디가 잘못됐고 어떻게 고쳐야 하는지"** 피드백을 제공한다.

- "어디(where)" + "어떻게(why/how)" 설명은 **Gemini**가 담당 (영상 네이티브, 시간 위치 탐지 가능)
- 임베딩은 **위치 탐지를 하지 않음**. 기준 영상 매칭과 유사도 점수만 담당.

## 비목표 (Non-goals)

- 임베딩 벡터로 프레임/구간 단위 정밀 위치 탐지 (DTW 정렬) — MVP 이후 정밀도 부족 시 도입
- 기준 영상 없이 일반적 오류를 찾는 기능
- 실시간(스트리밍) 처리

## 핵심 설계 결정

- **임베딩 벡터를 Gemini에 넣지 않는다.** Gemini API는 임의 임베딩 텐서를 입력으로 받지 못함. Gemini에는 **실제 영상/프레임**을 전달한다.
- 짧은 영상 기준이므로, 위치 탐지 부담을 Gemini에 넘기고 임베딩은 "영상 1개 → 벡터 1개"의 단순 구조로 둔다.

## 아키텍처

### 구성 요소

1. **임베딩 모듈**
   - 입력: 영상 1개 → 출력: 벡터 1개
   - 모델: **VideoMAE v2 (base)** — 로컬 RTX 4060 (VRAM 8GB) 추론
   - 용도:
     1. 사용자 영상에 맞는 **기준 영상 매칭/검색**
     2. 기준 대비 **유사도 점수** (합격/불합격, 얼마나 벗어났나)

2. **기준 영상 DB**
   - 기준 영상들의 임베딩 저장
   - 초기: numpy dict (메모리/파일)
   - 확장: 항목 많아지면 FAISS

3. **피드백 모듈 (Gemini)**
   - 입력: 사용자 영상(통째로) + (선택) 매칭된 기준 영상 + 프롬프트
   - 출력: "0:12에 ~문제, 이렇게 고쳐라" 형태의 텍스트 피드백

4. **출력**
   - 유사도 점수 + Gemini 텍스트 피드백

### 데이터 흐름

```
사용자 영상 ─┬─ VideoMAE v2 → 벡터 → 기준DB 비교 → 점수 + 매칭 기준영상
            └─ (원본 영상) ───────────────────────┐
                                 매칭 기준영상 ────┴─ Gemini → 텍스트 피드백
```

## 기술 스택 / 환경

- OS: Windows 11
- 패키지 매니저: `uv` (uv venv)
- Python: 3.11+
- 프레임워크: PyTorch
- 임베딩: VideoMAE v2 (base), 로컬 RTX 4060
- 피드백: Gemini API (영상 입력)
- 기준 DB: numpy → (확장) FAISS

## 에러 처리 / 고려사항

- 영상 디코딩 실패, 빈 영상, 지원 안 되는 코덱 → 명확한 에러 반환
- Gemini API: 영상 길이/용량 한도, 레이트리밋, 타임아웃 재시도
- 임베딩 차원/정규화 일관성 (코사인 유사도 사용 시 L2 정규화)

## 향후 확장

- 정밀도 부족 시: 클립/프레임 단위 임베딩 + DTW 정렬로 구간 위치 탐지 추가
- 임베딩 모델 업그레이드 경로: VideoMAE v2 → V-JEPA 2 → InternVideo2
- 기준 DB: numpy → FAISS

## 열린 질문 (구현 전 확정 필요)

- 영상 평균 길이 / 최대 길이 (Gemini 입력 한도 산정)
- 도메인 범위 (사람 동작 + 일반 장면 혼합)
- 유사도 점수의 합격/불합격 임계값 기준
