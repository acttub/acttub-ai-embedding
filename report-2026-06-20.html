진행 과정

  1. 환경 복구 완료

    기존 .venv가 다른 계정(C:\Users\RYU\…)에서 만들어진 거라 이 PC에선 Python 베이스를 못 찾아 깨져 있었음. uv 미설치 + Python 3.13만 존재.

    • pip install uv → uv 0.11.23 설치
    • uv sync → Python 3.11.15 기반 venv + 의존성 재현

  2. torch CUDA 전환 완료

    초기엔 CPU 빌드(2.12.1+cpu)라 RTX 4060 미사용. pyproject.toml에 PyTorch CUDA 인덱스를 추가해 GPU 빌드로 교체.

    cu124 인덱스는 torch 2.6까지만 있어 충돌 → torch 2.12.1이 존재하는 cu126으로 해결.

    [tool.uv.sources]
torch = { index = "pytorch-cu126" }
torchvision = { index = "pytorch-cu126" }

[[tool.uv.index]]
name = "pytorch-cu126"
url = "https://download.pytorch.org/whl/cu126"
explicit = true

    결과: torch 2.12.1+cu126, cuda available: True, NVIDIA GeForce RTX 4060

  3. top-K 검색 기능 — TDD 완료

    기존 match()(1등만)에 더해 search(vector, k)를 테스트 먼저 작성 후 구현.

    • 정렬·top-K·DB 크기 클램프 테스트 2개 추가 → Red → 구현 → Green
    • 반환: list[(ref_id, 코사인 유사도)], 유사도 내림차순

  4. 기준 영상 인덱스 구축 완료

    scripts/build_index.py 작성 — C-pro 전문가 영상 34개를 미리 임베딩해 index.npz로 저장. (기준 영상은 미리, 질의 영상만 실시간 임베딩하는 구조)

  5. 임베딩 모델 업그레이드: VideoMAE → V-JEPA 2 완료

    VideoMAE 임베딩은 유사도가 전부 0.97대로 뭉쳐 변별력이 약했음. transformers 네이티브 미지원인 VideoMAEv2 대신, 더 신형이고 네이티브 지원되는 V-JEPA 2 (Meta, ViT-L)로 교체.

  6. 웹 UI — Gradio 완료

    app.py 작성. 서버 기동 시 모델 + 인덱스를 1회 로드(GPU 상주), 업로드 영상만 실시간 임베딩 → 검색.

    • 입력: 질의 영상 업로드 + top-K 슬라이더
    • 출력: 가장 유사한 전문가 영상 재생 + top-K 순위표(파일명·유사도)

벡터 DB 필요 여부 (논의 결론)

지금 규모(수십~수천 개)에선 불필요. numpy brute-force(matrix @ query)가 더 빠르고 정확(근사 없음). 진짜 병목은 검색이 아니라 VJEPA2 임베딩(질의당 ~2초)이라 벡터DB로 안 빨라짐.

전환 시점: ① 벡터 10만+ → FAISS, ② 증분 추가/필터/멀티유저 서비스 → Qdrant·pgvector. 계획서 로드맵: numpy → FAISS.
